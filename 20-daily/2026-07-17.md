### 1. 單元測試全過≠系統沒問題
LLM 為了讓生成的程式碼通過所有單元測試，容易陷入「驗證梯度」的局部最優，反而犧牲整體系統效能與業務邏輯正確性。防禦方式是建立多層測試（單元＋整合＋系統）搭配效能基準與人工審查，而非只看測試綠燈就放行。

_類型：framework_

### 2. 部署 Agent 前先想好回滾路徑
AI Agent 會自信地做出錯誤決策卻毫不自知，因此企業級部署的核心原則是 fail-safe 優先於全自動化：先假設 Agent 一定會出錯，再反推回滾機制與人工介入點，而非等出包才補救。

### 3. 雲端帳單滯後，追不上 Agent 速度
傳統雲端計費警衛是為人類操作速度設計，偵測滯後可達一天，而 Agent 能在同一時間內發出海量請求。任何授權 Agent 存取雲端資源的團隊，都該額外建立不依賴官方帳單週期的即時用量監控與細粒度 IAM 權限。

### 4. 授權 Agent 前先備齊五項資產
把工作交給 AI Agent 前，組織需先講清楚：任務邊界、充分上下文、高品質標準、評估機制、以及哪些決策必須留給人工。少一項，Agent 的產出就難以信任。
