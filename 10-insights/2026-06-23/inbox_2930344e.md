## An Ex-Meta L8’s Agentic Engineering Setup

前 Meta L8 principal engineer Kun Chen 分享 agent 工程設置哲學與工具鏈。核心轉變是從直接寫代碼轉向「像工程經理一樣指揮 agent 團隊」——委派結果而非動作，透過自動化驗證保證品質。基礎設施採終端優先架構：WezTerm（跨平台一致性）、Claude Code 和 OpenCode（避免廠商鎖定）、Neovim + 插件（檔案瀏覽、git、搜尋）、Tmux（跨裝置持久會話透過 SSH）。提示技巧包括 OpenSuperWhisper（本地免費語音輸入加速 prompt 創建）、委派原則強調請求「結果」而非「動作」並解釋 why，抗拒接管控制以讓 agent 自主工作。複雜特性規劃用 Lavish Editor（互動 HTML 規劃介面，直接點擊元素標註變更快於長文本）。實現驗證包括 agent 端到端自動測試、gnhf orchestrator（複雜工作分解為 context-window 尺度單位，失敗自動 rollback 並重試）、no-mistakes 代碼審查工具（新 context 避免偏見、升級産品決策給人類、要求 E2E 證據，報告 68% 變更含缺陷被發現）。並行策略用 treehouse（抽象 git worktree 複雜性、自動管理預備 worktree 池及依賴）、custom tmux 標籤顯示進度，常見 5-10 並行任務。遠程支援透過 Tailscale + SSH 和 mosh（優化行動網路終端狀態）。Chen 單日出貨「30+ 高品質 PR」——相比傳統開發數量級提升。關鍵洞察是「絕不接受拖慢你的東西」，客製工具填補商用 agent 平台與真實工作流的空隙，friction 移除工具和 agent 使用同樣重要。

### 重點
- 委派結果不委派動作：最佳 prompting 是要求 outcome（"audit 命名規範確保一致性"）而非指令（"rename 變數"），啟用 agent 自主長任務
- no-mistakes 代碼審查：68% 變更含缺陷被自動化新 context 審查發現；升級産品決策給人類
- gnhf + treehouse 並行化：複雜工作自動分解、失敗自動 rollback、git worktree 自動管理，支持 5-10 並行任務日出貨 30+ PR
