## Why I Stopped Using LLMs as Search Engines

作者發現 LLM 做為搜尋引擎的根本局限：無狀態性導致每次新對話都須重新輸入完整上下文，浪費時間。回應方案是自行開發 FIL（Flexible Information Layer）——一套 Markdown 為基礎的對話連續性協議。核心創新：將項目狀態分離為 STABLE（不變的定義、業務規則）與 DYNAMIC（實時狀態、決策）；DYNAMIC 再分為三層熱區（Hot/Warm/Cold，按存取頻率），類似 CPU cache。添加「真實性標籤」（[truth:official]、[truth:estimated] 等）以標示資訊可信度。零基礎設施（無伺服器、無資料庫）但依賴使用者手動操作或 Drive 連接進行持久化。

### 重點
- FIL 核心問題：LLM 無狀態性 → 每次新會話須重新輸入完整上下文，破壞工作流連續性
- 解決方案：Markdown 格式的 STABLE/DYNAMIC 分層架構 + Hot/Warm/Cold 三層熱區機制，加速 context 加載與 attention 管理
- 真實性標籤系統（[truth:official]、[truth:estimated] 等）強制標示資訊來源及可靠性，避免 LLM 在不確定基礎上推理
