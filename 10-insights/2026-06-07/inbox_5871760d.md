## Claude Code as Daily Driver: Scars from the .md Contract

Claude Code 使用者 Zac Smith（Gauntlet AI 工程師）深入分析了使用該工具的實際成本與配置陷阱。他發現 Claude Code 的規劃器進入成本迴圈的根本原因：預設的 `CLAUDE_CODE_MAX_OUTPUT_TOKENS` 設為 8192，導致規劃器多次截斷草稿簿並在一次重構任務中重複讀取同一個 4000 行檔案 7 次。將上限提升至 16384 解決了這個低效率問題。他的技術棧包括 Vite + React、Firebase（認證 / Firestore）、Vitest 與 Playwright 等。Smith 指出 Claude Code 官方文檔涵蓋約 60% 的實務需求，剩餘 40% 需透過原始碼探索或實驗學習，而後者會產生大量 token 消耗。

### 重點
- Claude Code 配置陷阱：CLAUDE_CODE_MAX_OUTPUT_TOKENS 預設 8192 導致規劃器迴圈讀檔，改為 16384 解決
- 一次重構任務成本過高：規劃器在 40 分鐘內重複讀取 4000 行程式碼 7 次，造成不必要的 token 浪費
- 文檔覆蓋率 60%：官方文檔不足，剩餘實務細節需從原始碼或實驗學習，增加成本
