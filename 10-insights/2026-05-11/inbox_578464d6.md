## Why is opencode so slow in processing the prompt with llama server?

用戶報告本地運行 opencode + llama-server（Qwen3.6-35B，推理速度 21 t/s）時 prompt 處理延遲過高。硬體為 32GB RAM + 780M iGPU，llama.cpp 啟動參數包含 flash attention、65536 context、q8_0 KV cache 量化，系統仍有 8GB+ 可用 RAM，但 opencode 對每次輸入的處理時間達分鐘級。用戶通過對比 pi.dev 發現：pi.dev 延遲顯著更低，其系統 prompt 遠小於 opencode。表明系統 prompt 大小為 opencode 延遲的主要驅動因素。

### 重點
- 推理速度 21 t/s 正常，但 opencode 前端 prompt 處理延遲達分鐘級，與 RAM 不足無關
- 系統 prompt 大小與延遲強相關：pi.dev 系統 prompt 精簡，延遲明顯更低，優化系統 prompt 可能為主要改進方向
- 環境：llama.cpp with flash-attn、q8_0 context kv cache、-c 65536、-t 16 線程、-ngl 99 GPU offload
