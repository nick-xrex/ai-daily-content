## Any news (or hope) of Qwen-3.6 14B and 9B distills for local coding ?

社群用戶回報在 RTX 1000 6GB VRAM GPU 上使用 Qwen-3.5 9B 的遭遇。遭遇問題包括：目錄結構處理不當（產生過度嵌套層級）、測試結果判定錯誤。用戶詢問是否會推出 Qwen-3.6 的 9B 和 14B 蒸餾版本，期待改善工具呼叫能力。同樣提示詞在 Gemini-2.5-flash 上無此問題，暗示缺陷來自模型而非工具框架。

### 重點
- Qwen-3.5 9B 在 6GB VRAM 上的工具呼叫缺陷，特別是目錄操作和結果判定
- 社群期待 Qwen-3.6 提供 9B、14B 蒸餾版本以適配小 GPU，改善工具能力
- 對比測試顯示 Gemini-2.5-flash 無同類問題，指向模型層級的工具呼叫實現差異

As the title suggests. I'm already testing (with some success, and few challenges) usage of Qwen-3.5 9B with a new work laptop that I've received with RTX 1000 6GB VRAM (I know it seems like a joke in today's time and age). I am using it with `pi` as the terminal coding harness. The issue I am facing with Qwen-3.5 9B is that I've encountered some (relatively infrequent) issues around: How it handles directories / folders - more than once, strangely I got a deeply nested folder structure for final code/test artefacts Recognized test run to be failure, while it was actually a success Same prompts when used with gemini-2.5-flash and gemini-2.5-flash-lite don't see such issues, indicating the possibility that the issue is not with `pi`. I've read some reports of `pi` sometimes struggling with Qwen-3.5 tool-calling, and that is apparently fixed in Qwen-3.6.
