## What pip 26.1 Means for Everyday Python Developers

PyBrief 週刊第 1 期深度分析 pip 26.1 發布的六項重要變更：（1）Python 3.9 支援終止，pip 26.1 僅支援 3.10+，對應 Python 3.9 於 2025 年 10 月 EOL；（2）實驗性 PEP 751 pylock.toml 鎖檔支援（`pip install -r pylock.toml`），但當前無法選擇 extras、限制 VCS/本地路徑混用、無檔案大小驗證；（3）新的 --uploaded-prior-to 旗標實現 dependency cooldowns（如 `pip install --uploaded-prior-to=P3D pip` 僅允許 3 天前上傳的套件），目標減少受洩露上游的曝露，但建議配合 pip-audit/Dependabot；（4）2020 年現代依賴解析器的邊界案例修正（extras+URL constraints、雜湊驗證），朝向 2027 年移除舊解析器；（5）安全修復：CVE-2026-3219（tar.gz 被誤為 ZIP）和 CVE-2026-6357（自我更新漏洞），升級 urllib3 2.6.3；（6）棄用 PIP_CONSTRAINT for build deps，遷移至 --build-constraint。

### 重點
- Python 3.9 支援終止強制升級環境；pylock.toml 適合「受控、隔離工作流」而非完全取代 requirements.txt（當前限制包括無法選擇 extras、VCS 路徑混用受限）
- Dependency cooldowns（--uploaded-prior-to）的決策框架：權衡供應鏈安全（延遲 3 天減少洩露風險）vs 安全補丁延遲；pip 官方建議配合外部監控工具如 pip-audit 使用
- 兩個已修復的 CVE：tar.gz/ZIP 誤識別漏洞改用伺服器 Content-Type 優先、檔案副檔名次之；pip 版本檢查提早執行防止安裝時代碼執行。urllib3 升級至 2.6.3 移除 1.x 過時攻擊面
