## Harness Engineering: How to Build Software When Humans Steer, Agents Execute — Ryan Lopopolo, OpenAI

Ryan Lopopolo (OpenAI) 提出「Harness Engineering」：人類掌舵、代理執行的軟體建構新範式。核心理念為代碼已成免費資源，稀缺的是人類時間和注意力；模型能力已等同人類工程師，故角色轉向系統思考與委派。五層架構由下至上為代碼庫（750 PNPM 包強制一致性）、CI/CD Pipeline（每次提交由代理審查）、文件與標準（ADRs、QA 模板、分角色指南）、Lints+Tests+護欄（自訂 ESLint、代碼結構測試）、Skills（5-10 高槓桿技能封裝基礎設施）、CodeEx 代理、Ticket。核心實踐為「Garbage Collection Friday」每週識別並永久消除 slop 模式，Prompt Injection 在 lints、tests、reviewer agents、錯誤訊息多點觸發。關鍵指標為 3-5 PR/日/工程師、<1 日 PR 年齡、15 代理並行遷移完成。

### 重點
- 五層 Harness 架構：代碼庫（750 包+強制一致）→ CI/CD（代理審查）→ 文件/標準（角色分區 ADR）→ Lints/Tests → Skills（高槓桿能力）→ 代理執行，代碼視為可拋棄的編譯產物
- Garbage Collection Friday 實踐：每週識別代理 slop 模式、轉換為文件 → lints → reviewer agents，永久改善代理行為，比逐 PR 評論高效
- Token 預算分配：規劃/tickets 佔 1/3、文件/庫上下文佔 1/3、實施/CI 佔 1/3；Prompt Injection 多點觸發（lints、tests、reviewer agents、錯誤訊息），15 代理並行遷移相比 6 月單人完成
