# ESQL Masterclass Part 2: Understanding Data Types in ESQL

<figure><img alt="ESQL Masterclass Part 2: Data Types for IBM ACE." src="https://cdn-images-1.medium.com/max/1024/1*XZjdRgOyltHT-Y2CwBOWQA.png" /><figcaption>(Understanding Data Types in ESQL)</figcaption></figure><p>In Part 1 of this series, we explored why <strong>Extended Structured Query Language (ESQL)</strong> remains the powerhouse of message transformation in <strong>IBM App Connect Enterprise (ACE)</strong>. But to write efficient, bug-free code, you must understand the “nature” of the data you are handling.</p><p>In ESQL, a <strong>Data Type</strong> isn’t just a label — it determines how the integration engine processes, calculates, and stores your message information.</p><p>ESQL supports <strong>six core groups</strong> of data types (plus the specialized <strong>ROW</strong> type). Let’s break them down.</p><h3>String Data Types</h3><p>Strings in ESQL are more than just text. They are divided into three specific categories:</p><p><strong>CHARACTER</strong></p><p>The <em>CHARACTER </em>data type is used to store Unicode text strings. It is the most common data type for handling names, descriptions, and message content.<br /><strong><em>Syntax: </em></strong><em>Place any number of characters inside single quotes.</em><br /><strong><em>Note:</em></strong> <em>To include a single quote inside your string, use two single quotes to escape it.</em></p><pre>-- 1. Basic Declaration<br />DECLARE seriesMsg CHARACTER;<br />DECLARE fullSubTopic CHARACTER;<br />DECLARE product CHARACTER;<br /><br />-- 2. Basic Assignment<br />SET seriesMsg = 'Welcome to ESQL Masterclass Series';<br /><br />-- 3. Concatenation using the || operator<br />SET fullSubTopic = 'String' || ' ' || 'Data Type';<br /><br />-- 4. Handling Single Quotes (Escape with another single quote)<br />SET product = 'IBM ''App Connect Enterprise'' Series';</pre><p><strong>BIT</strong></p><p>The <strong>BIT</strong> data type stores a variable-length string of binary digits (<strong>0s and 1s</strong>).<br /><strong><em>Usage: </em></strong><em>Mainly used for binary data that does not have a fixed number of bytes.</em><br /><strong><em>Syntax: </em></strong><em>Use the letter </em><strong><em>B</em></strong><em> (upper or lowercase) followed by the digits in single quotes.</em></p><pre>-- 1. Basic Declaration<br />DECLARE binaryFlag BIT;<br /><br />-- 2. Assignment (Use 'B' prefix)<br />SET binaryFlag = B'101101';<br /><br />-- 3. Appending Bits<br />SET binaryFlag = binaryFlag || B'00'; -- Result: B'10110100'<br /><br />-- 4. Handling Bits in Logic<br />IF binaryFlag = B'10110100' THEN<br />    SET OutputRoot.XMLNSC.Output.Status = 'Active_Flag_Set';<br />END IF;</pre><p><strong>BLOB</strong></p><p>The <strong>BLOB</strong> (Binary Large Object) data type stores a string of 8-bit bytes.<br /><strong><em>Usage: </em></strong><em>Used for encrypted data, raw file contents, or when converting text into a specific encoding (CCSID) for external systems.<br /></em><strong><em>Syntax: </em></strong><em>Use the letter X followed by hexadecimal digits (0–9 and A-F) in single quotes.<br /></em><strong><em>Rule: </em></strong><em>You must have an even number of digits (two digits per byte).</em></p><pre>-- 1. Basic Declaration<br />DECLARE rawPayload BLOB;<br />DECLARE payload BLOB;<br />DECLARE secureToken BLOB;<br /><br />-- 2. Assignment (Use 'X' prefix)<br />SET rawPayload = X'48656c6c6f'; -- Hex for &quot;Hello&quot;<br /><br />-- Note: Digits must be in pairs (0-9, A-F)<br />SET secureToken = X'ABC123DEF456';<br /><br />-- 3. Handling BLOBs in Expressions<br />-- Converting CHARACTER to BLOB<br />SET payload = CAST('Message' AS BLOB CCSID 1208);</pre><h3><strong>Numeric Data Types</strong></h3><p>In ESQL, <strong>Numeric</strong> values are handled by three primary data types. Choosing the right one is essential for balancing calculation speed with mathematical precision.</p><p><strong>DECIMAL</strong></p><p>The <strong>DECIMAL</strong> data type is the “gold standard” for accuracy. It stores numbers exactly, making it ideal for financial transactions where rounding errors are not an option.<br /><strong><em>Precision:</em></strong> <em>The total count of digits (before and after the decimal).</em><br /><strong><em>Scale: </em></strong><em>The count of digits after the decimal point.</em><br /><strong><em>Rounding:</em></strong> <em>Automatic adjustment to fit the allowed digit limit.</em></p><p><strong>Key Constraints:</strong><br /><em> </em><strong><em>Precision Range:</em></strong><em> Minimum of </em><strong><em>1</em></strong><em> to a maximum of </em><strong><em>34</em></strong><em> digits.</em><br /><strong><em>Scale Range:</em></strong><em> From </em><strong><em>-999,999,999</em></strong><em> to </em><strong><em>+999,999,999</em></strong><em>.</em><br /><strong><em>Note:</em></strong><em> You cannot set precision/scale during a simple declaration; they are set automatically. However, you can specify them when using a </em><strong><em>CAST</em></strong><em> function.</em></p><pre>-- 1. Basic Declaration and Assignment<br />DECLARE totalAmount DECIMAL; <br />DECLARE discount DECIMAL;<br />SET totalAmount = 9850.75;<br /><br />-- 2. Using CAST for specific Precision (10) and Scale (2)<br />SET totalAmount = CAST(9850.755 AS DECIMAL(10, 2)); -- Result: 9850.76 (Rounded to 2 decimal places)<br /><br />-- 3. Handling Decimals in Logic<br />-- Precise calculation for a 10% discount<br />SET discount = totalAmount * 0.10;<br /><br />IF totalAmount &gt; 5000.00 THEN<br />    SET OutputRoot.XMLNSC.Output.FinalTotal = totalAmount - discount;<br />END IF;</pre><p><strong>FLOAT</strong></p><p>The <strong>FLOAT</strong> data type stores an <strong>approximate</strong> real number. It is highly efficient for scientific calculations but may involve tiny rounding differences.<br /><strong><em>Format: </em></strong><em>Uses a 64-bit base-2 format with a fraction and an exponent.<br /></em><strong><em>Range: </em></strong><em>Approximately ±1.7E–308 to ±1.7E+308.<br /></em><strong><em>Usage: </em></strong><em>Use this when speed is more important than absolute decimal perfection.</em></p><pre>-- 1. Basic Declaration<br />DECLARE piValue FLOAT;<br />DECLARE largeNumber FLOAT;<br /><br />-- 2. Assignment<br />SET piValue = 3.141592653589793;<br /><br />-- 3. Using Scientific Notation for extremely large values<br />SET largeNumber = 1.7E+308;<br /><br />-- 4. Handling Float in Math<br />-- Calculating a large volume or scientific result<br />DECLARE radius FLOAT 5.5;<br />DECLARE area FLOAT;<br /><br />SET area = piValue * (radius * radius); -- Result: 95.03317777109125</pre><p><strong>INTEGER</strong></p><p>The <strong>INTEGER</strong> data type stores whole numbers only (no decimals).<br /><strong><em>Format: </em></strong><em>Uses a 64-bit two’s complement format.<br /></em><strong><em>Range:</em></strong><em> From –9,223,372,036,854,775,808 to +9,223,372,036,854,775,807.<br /></em><strong><em>Usage: </em></strong><em>Best for counters, array indexes, and IDs.</em></p><pre>-- 1. Basic Declaration<br />DECLARE userCount INTEGER;<br />DECLARE errorCode INTEGER;<br />DECLARE   i       INTEGER 1;<br /><br />-- 2. Assignment<br />SET userCount = 1500;<br /><br />-- 3. Negative Integer Example<br />SET errorCode = -500;<br /><br />-- 4. Simple Arithmetic operation (Incrementing)<br />SET userCount = userCount + 1;<br /><br />-- 5. Using an Integer as an array index<br />SET OutputRoot.XMLNSC.Output.Item[i].userCount = userCount;</pre><h3>Datetime Data Types</h3><p>In ESQL, managing time accurately is vital for logging, auditing, and scheduling integrations. The <strong>Datetime</strong> group includes several types designed to handle specific calendar and clock values.</p><p><strong>DATE</strong></p><p>The <strong>DATE</strong> type stores a calendar date (Year, Month, Day) using the Gregorian format.<br /><strong><em>Syntax:</em></strong><em> Use the keyword DATE followed by a space, followed by a date in single quotation in the form ‘yyyy-MM-dd' format.<br /></em><strong><em>Note: </em></strong><em>You must include leading zeros for months and days (e.g., 06 instead of 6).</em></p><pre>-- 1. Basic Declaration<br />DECLARE dummyDate, expiry DATE;<br /><br />-- 2. Assignment (Stores a calendar date (Year, Month, Day).)<br />SET dummyDate = DATE '2026-03-30'; -- Represents March 30, 2026<br />SET expiry = DATE '2026-03-20';<br /><br />-- 3. Handling Date Logic (Used for checking deadlines and expiration.)<br />IF expiry &lt; CURRENT_DATE THEN<br />    SET OutputRoot.XMLNSC.Output.Status = 'Expired';<br />END IF;</pre><p><strong>TIME</strong></p><p>The <strong>TIME</strong> data type stores the <strong>local time</strong> of day in hours, minutes, seconds, and fractions of a second.<em><br /></em><strong><em>Syntax: </em></strong><em>The word TIME followed by a space, followed by a time in single quotation marks in the form ‘hh:mm:ss.ffffff’ (24-hour clock).<br /></em><strong><em>Constraint: </em></strong><em>Hours, minutes, and seconds must always have two digits (e.g., 09, not 9).<br /></em><strong><em>Note: </em></strong><em>The fractional seconds part is optional and supports up to 6 digits (microseconds).</em></p><pre>-- 1. Basic Declaration<br />DECLARE localTime TIME;<br /><br />-- 2. Assignment (Use the TIME keyword followed by 'hh:mm:ss.fff')<br />SET localTime = TIME '14:30:05.123'; <br /><br />-- 3. Assigning the current system time<br />DECLARE currentTime TIME CURRENT_TIME;<br /><br />-- 4. Handling Time in Logic (Used for time-of-day checks, such as identifying if a transaction occurred during business hours.)<br />-- Ensure leading zeros (09, not 9) for hours, minutes, and seconds<br />IF localTime &gt; TIME '09:00:00' AND localTime &lt; TIME '17:00:00' THEN<br />    SET OutputRoot.XMLNSC.Output.BusinessStatus = 'Within Hours';<br />ELSE<br />    SET OutputRoot.XMLNSC.Output.BusinessStatus = 'After Hours';<br />END IF;</pre><p><strong>GMTTIME</strong></p><p>The <strong>GMTTIME</strong> data type is functionally identical to the TIME type, but it specifically stores the time in <strong>Greenwich Mean Time (GMT)</strong>.<br /><strong><em>Syntax:</em></strong><em> Written exactly like a TIME literal, but using the keyword GMTTIME.<br /></em><strong><em>Usage:</em></strong><em> Essential for logging or auditing in global applications where servers are spread across different timezones.</em></p><pre>-- 1. Basic Declaration<br />DECLARE universalTime GMTTIME;<br /><br />-- 2. Assignment<br />-- Use the GMTTIME keyword followed by 'hh:mm:ss.ffffff'<br />SET universalTime = GMTTIME '10:05:30.450'; <br /><br />-- 3. Assigning the current universal system time<br />DECLARE currentGMT GMTTIME CURRENT_GMTTIME;<br /><br />-- 4. Handling GMTTIME in Global Logs<br />-- Ensure hours, minutes, and seconds have two digits (e.g., 08, not 8)<br />IF universalTime &lt; GMTTIME '12:00:00' THEN<br />    SET OutputRoot.XMLNSC.Output.Period = 'Morning GMT';<br />END IF;<br /><br />-- 5. Standardizing the output for a global API response<br />SET OutputRoot.XMLNSC.Output.SyncTime = CAST(currentGMT AS CHARACTER);</pre><p><strong>TIMESTAMP</strong></p><p>The <strong>TIMESTAMP</strong> data type stores both <strong>DATE</strong> and <strong>TIME</strong> together in a single value. This includes:<br /><strong><em>Date Components:</em></strong><em> Year, month, and day.<br /></em><strong><em>Time Components: </em></strong><em>Hours, minutes, seconds, and optional fractions of a second.</em></p><p><strong>Syntax &amp; Rules<br /><em>Syntax:</em></strong><em> Use the word TIMESTAMP followed by a space, followed by a time stamp in a single quotation in the form </em>‘yyyy-MM-dd HH:mm:ss.SSSSSS'<br /><strong><em>Constraint:</em></strong><em> The year must have 4 digits (e.g., 2025). The month, day, hour, and minute must each have 2 digits (e.g., 06 instead of 6).<br /></em><strong><em>Fractions: </em></strong><em>The fractional seconds part is optional and can have between 0 to 6 digits.</em></p><pre>-- 1. Basic Declaration<br />DECLARE logEntry       TIMESTAMP;<br />DECLARE currentLocalTS TIMESTAMP;<br /><br />-- 2. Assignment<br />-- Use the TIMESTAMP keyword followed by 'yyyy-MM-dd HH:mm:ss.SSSSSS'<br />SET logEntry = TIMESTAMP '2026-04-02 14:30:00.125'; <br /><br />-- 3. Capturing the current local system date and time<br /> SET currentLocalTS = CURRENT_TIMESTAMP;<br /><br />-- 4. Handling Timestamps in Audit Logs<br />-- Checking if a transaction is backdated<br />IF logEntry &lt; CURRENT_TIMESTAMP - INTERVAL '1' DAY THEN<br />    SET OutputRoot.XMLNSC.Output.Alert = 'Backdated Transaction detected';<br />END IF;<br /><br />-- 5. Output Mapping<br />SET OutputRoot.XMLNSC.Output.ProcessedAt = CAST(currentLocalTS AS CHARACTER);</pre><p><strong>GMTTIMESTAMP</strong></p><p>The <strong>GMTTIMESTAMP</strong> data type is similar to the standard TIMESTAMP, but it specifically stores the date and time in <strong>Greenwich Mean Time (GMT)</strong>.<br /><strong><em>Syntax:</em></strong><em> Written exactly like a TIMESTAMP literal, but using the keyword GMTTIMESTAMP.<br /></em><strong><em>Usage:</em></strong><em> This is the industry standard for logging transactions that occur across different global regions to ensure time consistency.</em></p><pre>  -- 1. Basic Declaration<br />  DECLARE globalLog GMTTIMESTAMP;<br />  DECLARE currentGlobalTS GMTTIMESTAMP;<br />  <br />  -- 2. Assignment<br />  -- Use the GMTTIMESTAMP keyword followed by 'yyyy-MM-dd HH:mm:ss.SSSSSS'<br />  SET globalLog = GMTTIMESTAMP '2026-04-02 10:05:15.123456';<br />  <br />  -- 3. Capturing the current universal system date and time<br />  SET currentGlobalTS = CURRENT_GMTTIMESTAMP;<br />  <br />  -- 4. Handling GMTTIMESTAMP in Global Apps<br />  -- Standardizing a transaction timestamp for a cross-border App<br />  SET OutputRoot.XMLNSC.Output.TransactionID = 'TXN_995';<br />  SET OutputRoot.XMLNSC.Output.UniversalTime = CAST(currentGlobalTS AS CHARACTER);<br />  <br />  -- 5. Comparing logs against a 24-hour global window<br />  IF globalLog &lt; CURRENT_GMTTIMESTAMP - INTERVAL '24' HOUR THEN<br />   SET OutputRoot.XMLNSC.Output.Status = 'Archive Candidate';<br />  END IF;</pre><p><strong>INTERVAL</strong></p><p>The INTERVAL data type has several subtypes, allowing you to store specific kinds of time durations ranging from years down to seconds.</p><p><strong>Available Subtypes:<br /><em>Year/Month: </em></strong><em>YEAR, MONTH, YEAR TO MONTH<br /></em><strong><em>Day/Time: </em></strong><em>DAY, HOUR, MINUTE, SECOND<br /></em><strong><em>Combinations:</em></strong><em> DAY TO HOUR, DAY TO MINUTE, DAY TO SECOND, HOUR TO MINUTE, HOUR TO SECOND, MINUTE TO SECOND</em></p><p><strong>Syntax &amp; Rules:<br /><em>Syntax:</em></strong><em> Use the word INTERVAL followed by the duration in single quotes and the specific subtype keyword.<br /></em><strong><em>Positive/Negative: </em></strong><em>You can store both positive and negative durations.<br />Combined Format: For types like YEAR TO MONTH, use a hyphen to separate units (e.g., ‘5–06’).</em></p><pre>  -- 1. Basic Declaration<br />  DECLARE gracePeriod INTERVAL;<br />  DECLARE duration INTERVAL;<br />  DECLARE preciseDelay INTERVAL;<br />  DECLARE ageInterval INTERVAL;<br />  <br />  -- 2. Assignment<br />  -- 2.1. Single unit: A duration of 30 days<br />  SET gracePeriod = INTERVAL '30' DAY;<br />  <br />  -- 2.2. Combined unit: A negative duration of 5 years and 6 months<br />  SET duration = INTERVAL '-5-06' YEAR TO MONTH;<br />  <br />  -- 2.3. Precise duration: 1 day, 2 hours, 3 minutes, and 4 seconds<br />  SET preciseDelay = INTERVAL '1 02:03:04' DAY TO SECOND;<br />  <br />  -- 3. Calculate an Expiry Date (Today + 1 Year)<br />  SET OutputRoot.XMLNSC.Output.ExpiryDate = CURRENT_DATE + INTERVAL '1' YEAR;<br />  <br />  -- 4. Schedule a Retry (Now + 15 Minutes)<br />  SET OutputRoot.XMLNSC.Output.RetryAt = CURRENT_TIMESTAMP + INTERVAL '15' MINUTE;<br />  <br />  -- 5. Calculating the difference between two timestamps results in an INTERVAL<br />  SET OutputRoot.XMLNSC.Output.ProcessingTime = (CURRENT_TIMESTAMP - Environment.StartTime) SECOND;<br />  <br />  -- 6. Adding Durations<br />  -- 6.1 Calculate an Expiry Date (1 Year from today)<br />  DECLARE expiryDate DATE CURRENT_DATE + INTERVAL '1' YEAR;<br /><br />  -- Schedule the Next Run (12 Hours from now)<br />  DECLARE nextRun TIMESTAMP CURRENT_TIMESTAMP + INTERVAL '12' HOUR;<br />  <br />  -- 7. Calculate how many days since a specific date<br />  DECLARE daysSince DATE DATE '2025-01-01';<br />  SET ageInterval = (CURRENT_DATE - daysSince) DAY;</pre><h3>Boolean Data Types</h3><p>The <strong>BOOLEAN</strong> data type is the engine of logic in ESQL. It is used to evaluate conditions and control the path of your message flow. Unlike many other programming languages that only support two states, ESQL supports <strong>three</strong>.</p><p><strong>BOOLEAN States:<br /></strong>A Boolean value in ESQL can represent one of the following:<br /><strong><em>TRUE: </em></strong><em>The condition is met.<br /></em><strong><em>FALSE: </em></strong><em>The condition is not met.<br /></em><strong><em>UNKNOWN: </em></strong><em>Represented when a value is </em>NULL <em>or cannot be determined.</em></p><p><strong>Syntax Rule:<br /><em>Literals: </em></strong><em>Written using the keywords TRUE, FALSE, and UNKNOWN.<br /></em><strong><em>Case Sensitivity: </em></strong><em>Boolean literals are not case-sensitive. You can write them as </em>TRUE<em>, </em>true <em>or even </em>true <em>— the ESQL compiler treats them the same.</em></p><pre>  -- 1. Basic Declaration<br />  DECLARE isRecordValid        BOOLEAN;<br />  DECLARE isProcessingComplete BOOLEAN;<br />  DECLARE status               BOOLEAN;<br />  <br />  -- 2. Assignment<br />  -- Assignments are case-insensitive (TRUE, true, True are all valid)<br />  SET isRecordValid = TRUE;<br />  SET isProcessingComplete = false;<br />  <br />  -- 3. UNKNOWN typically occurs when comparing a NULL value<br />  SET status = UNKNOWN;<br />  <br />  -- 4. Using BOOLEAN in Logic<br />  -- Checking conditions to determine the output status<br />  IF isRecordValid THEN<br />     SET OutputRoot.XMLNSC.Output.Status = 'SUCCESS';<br />  ELSEIF NOT isRecordValid AND isProcessingComplete = TRUE THEN<br />     SET OutputRoot.XMLNSC.Output.Status = 'FAILED';<br />  ELSE<br />     -- Handles the UNKNOWN state<br />     SET OutputRoot.XMLNSC.Output.Status = 'PENDING_VERIFICATION';<br />  END IF;</pre><h3>Null Data Types</h3><p>In ESQL, <strong>NULL</strong> is not just a value — it is a <strong>special state</strong>. Understanding how to handle NULLs is the difference between a robust integration and one that crashes when data is missing.</p><h4>Understanding the NULL State</h4><p>The <strong>NULL</strong> data type represents a value that is unknown, undefined, or uninitialized. It acts as a placeholder for data that simply isn’t there.</p><p><strong><em>Not Zero, Not Empty:</em></strong><em> NULL is strictly not the same as a numeric 0 or an empty string ‘ ’.<br /></em><strong><em>Universal Presence:</em></strong><em> Almost every data type in ESQL (Strings, Numerics, Datetimes) can exist in a NULL state.<br /></em><strong><em>The “NULL Effect”: </em></strong><em>In ESQL, if any part of a mathematical or logical expression is NULL, the entire result typically becomes NULL.</em><br /><strong><em>Key Rule: </em></strong><em>All NULL values are treated as the same data type. This “NULL type” has exactly one possible value: NULL.</em></p><pre>  -- 1. Basic Declaration<br />  DECLARE price INTEGER 100;<br />  <br />  -- 2. Initializing a variable as unprovided<br />  DECLARE middleName CHARACTER NULL;<br />  DECLARE tax INTEGER;<br />  <br />  -- 3. Assignment (The NULL data type represents a special state where a value is unknown, undefined, or missing.)<br />  SET tax = NULL;<br />  <br />  -- 4. Explicitly removing a field or marking it as missing in the tree<br />  SET OutputRoot.XMLNSC.Output.TemporaryData = NULL;<br />  <br />  -- 5. Assigning a NULL state directly to a field<br />  SET OutputRoot.XMLNSC.Output.Status VALUE = NULL;<br />  <br />  -- 6. Handling NULL in Expressions <br />  -- Note: NULL is &quot;infectious.&quot; If any part of a mathematical or string operation is NULL, the expression returns NULL.)<br />  SET OutputRoot.XMLNSC.Output.Total = price + tax; -- Result: NULL<br />  <br />  -- Use IS NULL or IS NOT NULL for checks (NEVER use '= NULL')<br />  IF middleName IS NULL THEN<br />   SET OutputRoot.XMLNSC.Output.NameStatus = 'Incomplete Name';<br />  END IF;</pre><h3>Reference Data Type</h3><p>The <strong>REFERENCE</strong> data type is one of the most powerful performance tools in ESQL. Think of it as a <strong>“Pointer”</strong> or a <strong>“Shortcut”</strong> to a specific location within a message tree. Instead of making the ESQL engine navigate a long path (e.g. <em>InputRoot.XMLNSC.Invoice.Customer.Details</em> ) every single time, you &quot;park&quot; a reference at that location for instant access.</p><h4>Understanding the Pointer Logic</h4><p>A <strong>REFERENCE</strong> variable stores the <strong>location</strong> of a field, not the value itself.</p><p><strong><em>The Path: </em></strong><em>It is written as a series of path separated by periods ( . ).<br /></em><strong><em>Correlation Name: </em></strong><em>The first part of the path (like InputRoot or Environment) identifies the starting point, while the rest describes the relative path to the target field.<br /></em><strong><em>Input Modification: </em></strong><em>A unique power of the </em><strong><em>REFERENCE </em></strong><em>type is that it allows you to modify elements even within the Input message tree (locally within the module), which is normally considered read-only.<br /></em><strong><em>Key Restriction: </em></strong><em>A reference can point to message fields, rows, or scalar variables. However, it cannot point to constants, database tables, or other reference variables.</em></p><pre>  -- 1. Creating a reference to a nested structure with declaration<br />  DECLARE custInvcRef REFERENCE TO InputRoot.XMLNSC.Invoice.Customer.Details;<br />  <br />  -- Now, use the shortcut 'custInvcRef' instead of the full path<br />  SET OutputRoot.XMLNSC.Output.Customer.Name = custInvcRef.Name;<br />  SET OutputRoot.XMLNSC.Output.Customer.City = custInvcRef.Address.City;<br />  <br />  -- 2. Dynamic Navigation (MOVE)<br />  -- Initialize the reference to the first item in an array<br />  DECLARE prodRef REFERENCE TO InputRoot.XMLNSC.Invoice.Products.Product[1];<br />  DECLARE I INTEGER 1;<br /><br />  WHILE LASTMOVE(prodRef) DO<br />     -- Process current item logic<br />     SET OutputRoot.XMLNSC.Output.Products.Product[I].Name = prodRef.Name;<br />     SET OutputRoot.XMLNSC.Output.Products.Product[I].Price = prodRef.Price;<br />   <br />     SET I = I + 1;<br />     -- Move the pointer to the next sibling in the XML tree<br />     MOVE prodRef NEXTSIBLING;<br />  END WHILE;</pre><h3>Row Data Type</h3><p>The <strong>ROW</strong> data type is the most versatile structural tool in ESQL. While its name suggests a simple database record, it is actually a powerful <strong>in-memory tree structure</strong>. It allows you to build, store, and manipulate complex data hierarchies outside of the main message tree.</p><h4>Understanding the Tree Structure</h4><p>In a traditional database, a “row” is a fixed set of single values (scalars). However, an ESQL <strong>ROW</strong> is far more flexible:</p><p><strong><em>Open Tree:</em></strong><em> It is an ordered set of named values where each value can be a single piece of data (scalar) or another ROW.<br /></em><strong><em>No Fixed Limits:</em></strong><em> Unlike database rows, ESQL rows can grow dynamically, forming nested hierarchies with no restricted depth.<br /></em><strong><em>The “Scratchpad”:</em></strong><em> It is commonly used as a temporary storage area (like a local cache) within a module to hold data before it is mapped to the final output.<br /></em><strong><em>Key Difference: </em></strong><em>A table is a collection of rows (like a 2D array), but a single ESQL ROW can contain an entire nested tree of information.</em></p><pre>  -- 1.
